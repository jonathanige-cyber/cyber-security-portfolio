# Wireshark DNS Traffic Analysis

## Objective

Investigate what happens when a domain name is requested and use Wireshark to observe the DNS traffic generated by my Kali Linux virtual machine.

## Environment

* Operating System: Kali Linux
* Virtualisation: VirtualBox
* Network Interface: `eth0`
* Network Mode: NAT
* Tool: Wireshark

## Investigation

I started a Wireshark capture on the `eth0` interface and applied the following display filter:

```text
dns
```

I then generated DNS traffic using:

```bash
nslookup example.com
```

and later:

```bash
nslookup google.com
```

## DNS Query Observed

The DNS query packet for `example.com` contained:

| Field            | Result        |
| ---------------- | ------------- |
| Source IP        | `10.0.2.15`   |
| Destination IP   | `192.168.1.1` |
| Protocol         | DNS over UDP  |
| Source Port      | `48769`       |
| Destination Port | `53`          |
| Query            | `example.com` |
| Query Type       | `A`           |

The `A` record request asks DNS for an IPv4 address associated with the domain.

## DNS Response

The DNS response was sent from:

`192.168.1.1` → `10.0.2.15`

The response demonstrated that the DNS server processes the domain-name query and can return IP address information.

A successful DNS query for `google.com` also returned IPv4 and IPv6 addresses, which I observed in Wireshark under the DNS response's **Answers** section.

## What I Learned

This practical demonstrated the process involved when a computer needs to resolve a domain name.

The basic process observed was:

```text
Kali Linux
    ↓
DNS query
    ↓
192.168.1.1
    ↓
DNS response
    ↓
IP address returned
```

I also observed that DNS commonly uses UDP port `53` and that a DNS packet contains information such as the source and destination addresses, query name, query type and response data.

## Cybersecurity Relevance

Wireshark can be used to investigate network traffic and identify DNS activity.

Understanding normal DNS traffic is useful when learning to identify unusual DNS behaviour, investigate connectivity problems and analyse network activity during security investigations.

## Evidence

A Wireshark packet capture was performed using my own Kali Linux virtual machine and my own generated DNS traffic.
